## 1. Problem Understanding - Describe the problem your system solves.
System purpose: Purpose of the system is to manage registration for a single event with fixed capacity. The system must register users until capacity is reached and place additional users into a FIFO waitlist such that when a registered user is cancelled, the earliest waitlisted user is promoted to the registered list.

Inputs to the system:
user_id: String of user's username. Format is a non-empty string

capacity: Max value of users that can be registered for an event. Integer that is greater than or equal to 0



Outputs produced by the system:
UserStatus: Python object with 2 fields --> state: one of the following strings "registered", "waitlisted", "none" .  position: integer representing the 1-based waitlist position of user (integer must be at least 1 or greater) or None if user is not on waitlist

NotFound Exception: Exception raises if user cannot be found for cancellation

DuplicateRequest Exception: Exception raised if user tries to register but is already registered or on waitlist

message: String output to stdout providing explanation of waitlist promotions

Primary goal of the system:
To automatically handle registration, cancellation, and waitlist promotions for a fixed capacity event with deterministic behaviour

FR17. The system shall service simultaneous user requests (same timestamp, same user ids) in order of following priority: Registration, Cancellation, Query

## 5. Acceptance Criteria - Acceptance criteria define how system
behavior will be verified.

AC1:

Given: Number of registered users is equal to capacity (capacity is greater than 0), and users are on the waitlist
When: A registered user is cancelled
Then: system shall remove the earliest waitlisted user from the waitlist and into the registered users list, without asking operator for any further input

Linked Constraint ID(s): C1

AC2:

Given: Number of registered users is equal to capacity, and users are on the waitlist
When: A registered user is cancelled
Then: The system shall show which user was promoted from waitlist and why

Linked Constraint ID(s): C2

AC3:

Given: At least one user is on the waitlist
When: When a registered user cancels
Then: system shall output a message explaining which user cancelled, which user was promoted in under 100 characters

Linked Constraint ID(s): C3

AC4:

Given: A user is registered or on the waitlist
When: A operator attempts to register user with the same name
Then: System shall output a message explaining that user was not registered since user with same ID has been registered

Linked Constraint ID(s): C4

AC5

Given: Capacity is set to 0 for EventRegistration

When: There is a user registration attempt

Then: Place the user on the waitlist, maintaining FIFO ordering

Linked Constraint ID(s): C5



AC6


Given: Two or more user requests (different user_ids) arrive at the same timestamp

When: The system processes those requests

Then: The system shall process the requests in lexicographic order using the ASCII values of the characters in their user id

Linked Constraint ID(s): C6




AC7

Given: Two or more user requests (with same user_id) arrive at the same timestamp

When: The system processes those requests

Then: The system shall process the requests in order according to the following priority: Registration, Cancellation, Query

Linked Constraint ID(s): C7

AC8

Given: A user performs a single system action

When: The system completes processing of that action

Then: The system shall generate at most one output message describing the outcome of the action and no additional or repeated messages

Linked Constraint ID(s): C8

AC9

Given: The event has capacity 1 and currently has 0 registered users.

When: Two registration requests arrive at the same timestamp from users "Bob" and "Alice"

Then: The system shall process the requests in lexicographic order of their user_id, registering Alice and placing Bob on the waitlist.

Linked Constraint ID(s): C6

EC6:

Description: Multiple users on waitlist cancel at the same time. Users are removed from the waitlist in lexicographic order of their user_id, maintaining FIFO ordering of the list

Covered by Acceptance Criteria ID(s): AC#6

EC7:

Description: Multiple users on registered list cancel at the same time. Users are removed from in lexicographic order of their user_id, maintaining FIFO ordering of the list. Users on waitlist are promoted in FIFO order
Linked Constraint ID(s): C#6
Covered by Acceptance Criteria ID(s): AC#6

EC8:

Description: User 1 is earliest on waitlist when one user on registered list cancels and another user registers at same timestamp. Users who made request at same time are serviced in lexicographic order of their user_ids. If user who cancelled is first: First user is cancelled, then user 1 is promoted to registered list, then user who registered is put on end of waitlist. If user who registered is first then that user will be placed at end of waitlist, then user who cancelled will be removed from registered list, and lastly user 1 will be promoted.
Linked Constraint ID(s): C#6
Covered by Acceptance Criteria ID(s): AC#6

EC9:

Description: User is registered. System receives cancellation and query for that same user (same user_id) at same timestamp. User is removed from registered list, then query will return status of none
Linked Constraint ID(s): C#7
Covered by Acceptance Criteria ID(s): AC#7


EC10: 

Description: System message output would be more than 100 characters long because user id is too long. Any system message output will accommodate 8 characters for username while keeping the message to at most 100 characters. Use only first 8 letters of username.
Linked Constraint ID(s): C#3
Covered by Acceptance Criteria ID(s): AC#3
